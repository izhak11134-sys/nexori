# NEXORI

A new, responsive anime discovery website, built from scratch with vanilla JavaScript and Vite. The site keeps the dark violet, pink, and cyan direction of the supplied visual reference.

## Open as a single HTML file

Download [NEXORI.html](NEXORI.html), then open the downloaded file in a modern browser. This self-contained version now includes the actual Firebase sign-in/editor, CSS, JavaScript and all original illustrations. It bundles all modules inline and uses hash navigation, so it is built to open without a local server or Node installation. A prominent **כניסה לניהול האתר** button appears at the top of the HTML; **Owner sign-in** is also enlarged in the footer. Cloud reads, sign-in and saving require Internet access and the existing verified manager role. Public Web configuration is embedded, never passwords or privileged keys. Without configuration it displays setup instructions.

The bundled app passed real-SDK emulator checks over HTTP, plus opaque-origin sign-in/save checks without browser storage. Actual double-click `file://` navigation is blocked by the cloud browser's managed URL policy, so Windows/local-file compatibility still needs the operator's check. The existing working Windows local-server package remains available. Browser restrictions may make favorites or authentication temporary; Auth uses session storage where supported and falls back to memory otherwise.

GitHub's file page displays source code rather than running HTML. Use the file's **Download raw file** button and open it from your Downloads folder. Alternatively, download [NEXORI-HTML.zip](https://github.com/izhak11134-sys/nexori/raw/refs/heads/main/downloads/NEXORI-HTML.zip), extract it and double-click `NEXORI.html`; this archive contains only the HTML and Hebrew instructions. The HTML is regenerated by `npm run build:html` and `npm run build`; `npm run build:windows` refreshes both download archives.

## Manage content inside the website with Firebase

For **Windows**, download [NEXORI-Windows.zip](https://github.com/izhak11134-sys/nexori/raw/refs/heads/main/downloads/NEXORI-Windows.zip) and extract the complete archive. In the extracted `NEXORI-Windows` folder, open a terminal and run `node start-local.mjs`, then open `http://localhost:5173/admin` in the browser. This needs [Node.js LTS](https://nodejs.org/en/download) (22 or newer). The package includes the built main app and operator-supplied public Firebase Web configuration, never passwords or privileged keys. It serves only on loopback and requires no npm installation or Firebase CLI. Follow [the Hebrew Windows instructions](scripts/windows/README-Windows-he.txt), including adding `localhost` to Auth's authorized domains. Starting the package does not deploy Hosting.

**The automatic CMD/PowerShell launcher and repair ZIP were withdrawn after the operator reported an antivirus warning.** Do not disable protection, add exclusions or restore blocked files. The exact threat name and affected file are not yet available, so this is not classified as a false positive. The replacement contains no downloaded shell launcher or automatic extraction/browser process; a Windows antivirus scan remains unverified. If it is blocked, stop and inspect Protection History.

Maintainers refresh this download with `VITE_FIREBASE_USE_EMULATORS=false npm run build:windows` using the actual public Web configuration, Node and Python 3; verify it with `npm run test:windows`. Rebuild the package when application code changes. Published content changes are fetched from Firestore and do not require repackaging.

To preview on an **iPhone over your home Wi-Fi**, extract the latest Windows package and run `node start-local.mjs --lan` in its folder. The server prints the exact address to enter in Safari or Chrome on the phone. Both devices must be on the same local network and the computer must remain running. This optional mode binds one assigned private IPv4 address, accepts only peers in that interface's subnet and the matching Host, and defaults to port 5174. If the wrong adapter is selected, the server prints alternative `--lan=PRIVATE_IP` commands. Other devices on that subnet can view the site while the mode runs; this does not deploy Hosting. Default startup remains loopback-only. Allow Node.js on the trusted Windows Private firewall profile if prompted. Opening HTML through iPhone Files may use a limited document preview instead of a fully running browser page. See the [Hebrew instructions](scripts/windows/README-Windows-he.txt).

**Free services only: Firebase Spark, with no payment method or Cloud Billing.** The active editor now uses **Authentication and Firestore only**. Do not deploy Functions or activate Storage. See the [Spark plan](docs/firebase-spark-plan-he.md) and [Console guide in Hebrew](docs/firebase-console-setup-he.md).

The main Vite application and bundled HTML include an **Owner sign-in** footer link and Hebrew manager page (`/admin` on HTTP, `#/admin` in the HTML). A verified account with `admins/{uid}.active == true` can edit all existing cards inline, save private drafts across devices, upload images, apply changes and recover revisions. Card and inner-page titles/backgrounds are independent for all six worlds. The visitor design remains unchanged. Authentication prefers session storage with memory fallback; manager drafts are stored in Firestore.

PNG/JPEG/WebP inputs up to 2MiB are decoded and compressed in the browser to WebP, at most 1600 pixels on the longest side and 192KiB per image. Images use separate Firestore Bytes documents. Draft image access is restricted; staged public copies become readable only after an atomic release. Rules enforce ownership, approved record/field shapes, immutable versions, image references, size and release consistency; semantic text checks and image decoding run in the client. Private product notes/preparation URLs are removed before release. Text payloads are limited to 600KiB.

Version checks reject stale saves. Eight immutable schema documents validate all 81 existing records before a draft/release head is updated, within Firestore rule limits. Regenerate rules when changing the schema. Images, schema versions, revisions and rule-dependent reads consume Spark quotas. Old versions and abandoned staged documents are not automatically deleted; establish retention before launch. This is a bounded free development solution, not unlimited image hosting.

Public Web configuration is local/ignored and can be supplied through `.env.local` using `.env.example`; builds embed those public values. Never commit service-account credentials. Without configuration the original site works and `/admin` shows setup instructions. The operator reports that local sign-in/edit access now works after correcting the collection name from `admin` to `admins`. Actual cloud rules, billing and remote edits have not been independently inspected by the agent. No website or cloud rules were deployed by the agent.

## Production build

```sh
npm run build
npm run preview -- --port 4173 --strictPort
```

Deploy `dist/` to a static host configured to serve `index.html` for application routes such as `/collection`, `/product/midnight-ronin`, and `/guides/first-figure`. The hosting platform must also handle genuine HTTP 404s appropriately; the app supplies a not-found view for unknown paths.

## What works

- Responsive home, collection, concept details, anime worlds, journal articles, saved finds, and information pages.
- Local collection search, category filtering, alphabetical sorting, and browser history.
- Accessible search dialog and mobile navigation.
- Favorites stored locally in the browser; no account or server required.
- Local artwork, including an original generated cinematic PNG banner and SVG concept illustrations, with no external image or font dependencies.
- Homepage inspiration tabs and random concept discovery through **Surprise me**.

## Catalog structure and adding products later

The catalog now has five primary categories: **Figures & collectibles**, **Apparel & style**, **Desk & room**, **Replicas & props**, and **Accessories & small finds**. Each has explicit product types. Anime worlds are a separate classification; category, world, type, search and sort can be combined in shareable URLs and restored on refresh/history navigation. World pages link to their categories rather than a dead-end placeholder. Original concepts remain separate from franchise merchandise.

Use the [Hebrew product-placement guide](docs/product-placement-guide-he.md) for the full click map and classification rules, and the [product intake CSV](docs/product-intake-template.csv) to record future choices. The CSV contains planning slots, not actual products; it is not an automatic import or administration interface. Each item should have one record with a primary category, product type and world. Real listings still need merchant verification, permitted artwork and affiliate integration before publication.

Taxonomy lives in `src/data.js`; reusable URL/filter/validation helpers live in `src/catalog.js`. Standalone generation rejects duplicate product IDs, incompatible category/type combinations, unknown worlds and concepts incorrectly assigned to franchises. Run `npm run test:catalog` for the catalog contract checks.
