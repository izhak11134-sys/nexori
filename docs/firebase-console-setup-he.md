# חיבור NEXORI ל־Firebase Spark

המערכת הפעילה משתמשת ב־Auth וב־Firestore בלבד. אין להוסיף אמצעי תשלום, לשדרג ל־Blaze או להפעיל Functions/Storage. יצירת Production mode אינה תשלום. האתר יישאר בפיתוח עד שיהיה מוכן להשקה.

## מה כבר הושלם לפי דיווח המשתמש

פרויקט `nexori-development` נוצר, אפליקציית Web הוגדרה, Email/Password הופעל ומשתמש מנהל נוצר. Firestore Standard `(default)` נוצר ב־Iowa. המסמך `admins/<UID של משתמש Auth>` נשמר עם שדה `active` מסוג Boolean וערך `true`. UID נלקח מ־Authentication ולא מכתובת דוא״ל או Auto-ID. אין לפרסם סיסמה או מפתח service account בצ׳אט או במאגר.

הסוכן לא נכנס לחשבון בפועל ולא אימת חיוב, כללים או הרשאת מנהל בענן.

## הצעד הבא — כללי Firestore

1. פתח [את קובץ הכללים המעודכן ב־GitHub](https://github.com/izhak11134-sys/nexori/blob/main/firestore.rules) ולחץ **Raw** כדי להעתיק את תוכנו המלא.
2. ב־Firebase Console בחר `nexori-development` → **Firestore Database → Rules**.
3. החלף את כל תוכן העורך בתוכן הקובץ, מתחיל ב־`rules_version` עם ההערות שמעליו ועד הסוגר האחרון. אל תשלב עם כללי Test mode ואל תשתמש ב־`allow read, write: if true`.
4. לחץ **Publish** והמתן להודעת ההצלחה. זו פריסת הרשאות בלבד, ללא פרסום אתר או שדרוג מסלול.

אם נדרש לתקן את הסכמה בקוד, הפעל `npm run firebase:sync` והשתמש בקובץ שנוצר; אין לפרסם סכמה ישנה. חלופה למנהל עם Firebase CLI מחובר לחשבון היא `firebase deploy --project nexori-development --only firestore:rules`. אין צורך או הרשאה לפרוס Hosting במסגרת צעד זה.

## אימות הדוא״ל והכניסה

ביישום הראשי, הפועל דרך HTTP, לחץ **Owner sign-in** בפוטר או פתח `/admin`. השתמש בחשבון המנהל שלך. אם הדוא״ל טרם אומת, מסך הניהול מציע שליחת הודעת אימות. פתח את הקישור בדוא״ל, צא מהחשבון והיכנס שוב כדי לרענן את פרטי ההרשאה. לא קיימת הרשמת מנהלים מתוך האתר.

ב־Authentication → Settings → **Authorized domains**, אשר רק את שם המתחם שמשמש בפועל לבדיקה. פרויקטים חדשים אינם בהכרח כוללים `localhost` אוטומטית; הוסף אותו אם בודקים במחשב המקומי. אין להוסיף שם מתחם שהומצא או לפתוח אתר ציבורי כדי לבצע את הבדיקה. חלק מפעולות אימות דוא״ל תלויות בשם מתחם מורשה ובהגדרות הפעולה של Auth.

לאחר הכניסה, בדוק שינוי כותרת ותמונת רקע בטיוטה של Dragon Ball ובדוק שכותרת הכרטיסייה נותרה עצמאית. בדוק יציאה וכניסה מחדש, מבקר נפרד שלא רואה טיוטה, החלת שינויים ושחזור. החלה משנה את תוכן היישום המחובר לפרויקט; היא אינה יוצרת אתר Hosting. שמור גיבוי ובדוק מכסות Usage.

## פיתוח מקומי

העתק `.env.example` ל־`.env.local` ומלא את הגדרות אפליקציית ה־Web הציבוריות שסיפקת. אין צורך ב־Storage bucket או Functions region למערכת הנוכחית. לקישור האמיתי השאר `VITE_FIREBASE_USE_EMULATORS=false`. אחרי שינוי הגדרות הפעל מחדש Vite:

```sh
npm ci
npm run firebase:sync
npm run dev -- --port 5173 --strictPort
```

פתח `http://localhost:5173` **במחשב שבו השרת פועל**. כתובת localhost של סביבת הענן אינה תצוגה ציבורית במחשב המשתמש. קובצי `NEXORI.html` ו־`NEXORI-editor.html` הם תצוגה/גיבוי מקומיים ואינם כוללים את ניהול Firebase; הניהול המשולב הוא ביישום הראשי.

לבדיקות האמולטור בלבד השתמש בפרויקט `demo-nexori` ובקונפיגורציית הדמו. אין ליצור הרשאות מנהל בפרויקט אמיתי מתוך בדיקות. הפעל Auth/Firestore בלבד לפי README ומסמך הבדיקות.

## מגבלות לפני ההשקה

קרא [את תוכנית Spark](firebase-spark-plan-he.md) לגבי דחיסה, מכסות וגרסאות שאינן נמחקות אוטומטית. יש לבדוק חיבור אמיתי, הרשאות, אימות דוא״ל, גיבוי, שמירת נתונים והצהרות פרטיות לפני ההשקה. אין צורך ב־Storage CORS, Functions או Cloud Billing בשלב זה.
